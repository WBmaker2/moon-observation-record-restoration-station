# 달 관측 기록 복원소 초등학생 실사용 개선 설계

- 작성일: 2026-07-18
- 대상: 초등학교 3~4학년 개인 또는 2인 모둠
- 기준 버전: `3ff3acd`
- 관련 감사 기록: `.gstack/design-reports/design-audit-localhost-2026-07-18.md`

## 1. 목표

기존 기록 복원소의 과학적 정확성과 차분한 시각 콘셉트는 유지하면서, 초등학생이 모바일과 교실용 컴퓨터에서 다음 행동을 스스로 찾고 끝까지 활동할 수 있게 개선합니다.

완료 기준은 다음과 같습니다.

1. 첫 안내를 읽은 학생이 강요된 확인 작업 없이 달 모양 변화의 핵심 세 가지를 이해합니다.
2. 사건 화면에서는 지금 풀 단계만 크게 보이고, 완료한 단계와 다음 단계는 짧은 상태로 구분됩니다.
3. 학생이 어려운 과학 용어 때문에 행동을 멈추지 않도록 쉬운 말을 먼저 쓰고 과학 용어를 보조로 제공합니다.
4. 답을 덜 입력한 채 최종 확인을 누르는 일이 없고, 틀렸을 때 고칠 단계가 바로 열립니다.
5. 375px 화면에서도 현재 질문과 다음 버튼을 한 번의 짧은 스크롤 안에서 찾을 수 있습니다.
6. 기존 사건 5개, 단일 답 4개·복수 가능 답 1개, 앞뒤 근거와 판단 보류라는 교육 계약을 그대로 지킵니다.

## 2. 실사용 점검 결과

### 점검 조건

- 375×812 모바일, 768×1024 태블릿, 1280×720·1440×1000 데스크톱
- 첫 방문 → 안내 완료 → 첫 사건 날짜 확인 → 후보 선택 → 미완성 상태 제출
- 초등 3학년 수준의 짧은 문장 읽기와 손가락 터치를 기준으로 관찰
- 키보드 포커스, 버튼·라벨 크기, 오류 복구 위치도 함께 확인

### 학생이 잘할 수 있는 부분

- 달 그림이 크고 이름이 함께 있어 후보를 비교하기 쉽습니다.
- 남색·크림색 기록소 화면이 차분하고 활동의 이야기 분위기가 분명합니다.
- 드래그 없이 버튼·라디오·체크박스로 모든 활동을 수행할 수 있습니다.
- 날짜 순서 → 달 모양 → 앞뒤 근거 → 변화 → 확신의 학습 순서가 논리적입니다.
- 선택 행 전체가 눌리는 구조이며 기본 터치 높이도 충분합니다.

### 학생이 막힐 가능성이 큰 부분

1. 첫 안내에 달 카드 8개와 필수 체크 5개가 한꺼번에 나타납니다. 모바일에서는 시작 버튼까지 긴 스크롤이 필요합니다.
2. 안내 중에도 `사건 1 / 5`라고 표시되어 이미 문제를 풀기 시작한 것처럼 느껴집니다.
3. 첫 사건에서 아직 풀 수 없는 2~5단계가 모두 길게 보입니다. 375px 화면에서는 전체 길이가 약 2,500px 이상입니다.
4. 후보 하나만 고르면 `복원 확인하기`가 활성화됩니다. 누락된 답은 맨 아래 피드백에서 한꺼번에 알려 주므로 다시 위로 올라가 찾아야 합니다.
5. `대표 간격`, `삭 무렵`, `이지러지는`, `변화 방향이 바뀌는 지점`, `확실하게 복원`은 설명 없이 읽기 어렵습니다.
6. `지구에서 밝게 보이는 부분`이라는 긴 표현이 모든 선택지에서 반복되어 질문의 차이가 잘 드러나지 않습니다.
7. 첫 화면의 달 8개는 격자로만 보여, 밝은 부분이 커졌다가 보름 뒤 작아지고 다시 이어지는 순환이 약합니다.
8. `근거 고르기`에는 앞·뒤 정답 문장 두 개만 있고 둘 다 체크해야 합니다. 학생이 근거를 비교해 판단하기보다 필수 체크를 끝내는 활동이 됩니다.

## 3. 선택한 개선 접근

### 채택: 한 단계 집중형 학습 흐름

기존 사건 5개와 후보·변화 방향·확신도 정답 계약은 유지하고, 안내와 사건 표현 계층을 바꿉니다. 학생에게는 현재 질문 하나만 펼쳐 보여 주고, 완료한 질문은 한 줄 요약 카드로 접습니다. 다음 질문은 제목과 잠금 상태만 짧게 보여 줍니다. 근거 단계만 정답 문장 체크 방식에서 비교 선택 방식으로 개선합니다.

이 접근은 기존 후보·변화·확신 판정을 유지하면서 모바일 길이, 행동 우선순위, 오류 복구를 함께 개선합니다. 근거 판정만 실제 비교 선택에 맞게 확장합니다.

### 검토했지만 채택하지 않은 접근

- **기존 긴 폼 유지 + 간격 축소:** 구현 위험은 낮지만 비활성 단계와 긴 스크롤 문제가 남습니다.
- **한 화면짜리 완전한 마법사:** 매 단계가 별도 화면으로 바뀌어 집중은 쉽지만 앞뒤 기록을 계속 비교하기 어렵고 뒤로 가기 상태가 복잡해집니다.

## 4. 학생용 언어 원칙

### 기본 원칙

- 행동 문장은 한 문장에 한 동작만 씁니다.
- 쉬운 말을 먼저 쓰고 과학 용어는 괄호나 작은 보조 이름으로 제공합니다.
- `복원`, `관측`처럼 앱 이야기의 핵심 단어는 유지하되 처음 한 번 뜻을 설명합니다.
- 달 자체가 커지거나 작아진다고 쓰지 않고 항상 `밝은 부분`이 변한다고 씁니다.
- `틀렸어요`보다 `이 단계를 다시 살펴봐요`처럼 고칠 행동을 안내합니다.
- 버튼은 누르면 일어나는 일을 구체적으로 씁니다.

### 주요 문구 변경

| 현재 문구 | 개선 문구 | 이유 |
|---|---|---|
| 앞뒤 기록을 살펴 사라진 달 모양을 찾아요 | 앞뒤 기록을 보고 빈칸에 들어갈 달 모양을 찾아요 | `사라진`보다 화면의 빈칸과 직접 연결됩니다. |
| 대표 달 모형을 먼저 살펴봐요 | 달 모양이 바뀌는 순서를 먼저 봐요 | `대표 모형`보다 할 일이 분명합니다. |
| 아래 여덟 모양은 여러 날의 변화를 알아보기 쉽게 묶은 연습용 모형이에요. | 달은 날마다 조금씩 달라져요. 여기서는 알아보기 쉬운 8개 모양으로 연습해요. | 한 문장을 두 생각으로 나누고 쉬운 말부터 제시합니다. |
| 대표 모형 안내 확인 | 준비됐어요, 사건 시작! | 버튼 결과를 바로 알 수 있습니다. |
| 앞뒤 기록은 교육용 대표 간격이 비슷해요. | 앞 기록과 뒤 기록은 비슷한 간격으로 놓였어요. | `교육용 대표 간격`을 제거합니다. |
| 날짜 순서 확인했어요 | 1단계 완료, 달 모양 고르기 | 다음 행동을 안내합니다. |
| 빈 기록에 들어갈 대표 모양을 골라요 | 빈칸에 들어갈 달 모양을 골라요 | `대표`를 반복하지 않습니다. |
| 앞 기록과 뒤 기록을 근거로 골라요 | 왜 그렇게 생각했나요? 앞뒤 기록에서 하나씩 골라요. | `근거`를 질문과 행동으로 풉니다. |
| 밝게 보이는 부분의 변화 방향을 골라요 | 밝은 부분은 어떻게 바뀌고 있나요? | `변화 방향`을 구체적인 질문으로 바꿉니다. |
| 이 기록을 얼마나 확실하게 복원할 수 있나요? | 답을 하나로 정할 수 있나요? | 판단 기준을 직접 묻습니다. |
| 복원 확인하기 | 내 생각 확인하기 | 학생 자신의 추론을 확인한다는 뜻이 분명합니다. |
| 다시 근거를 살펴봐요 | 이 단계를 다시 살펴봐요 | 어느 단계가 열리는 흐름과 맞춥니다. |

### 달 이름 표시

각 달 카드는 쉬운 설명을 큰 글씨로, 교과 용어를 작은 글씨로 함께 보여 줍니다.

| 쉬운 설명 | 보조 이름 |
|---|---|
| 밝은 부분이 거의 없어요 | 삭 무렵 |
| 밝은 부분이 조금 커져요 | 초승 무렵 |
| 밝은 부분이 절반이에요 | 상현 무렵 |
| 보름달에 가까워져요 | 보름 전 |
| 밝은 부분이 가장 넓어요 | 보름달 |
| 밝은 부분이 조금 작아져요 | 보름 뒤 |
| 밝은 부분이 절반이에요 | 하현 무렵 |
| 밝은 부분이 아주 가늘어요 | 그믐 무렵 |

상현과 하현의 같은 `절반` 표현은 각각 `커지는 중`, `작아지는 중` 구간 안에 배치하여 구분합니다. 좌우 밝은 방향 하나만으로 정답을 가르치지 않습니다.

## 5. 화면과 상호작용 설계

### 5.1 헤더

- 안내 화면 상태는 `준비 단계 · 사건 5개`로 표시합니다.
- 사건 화면은 기존처럼 `사건 1 / 5 · 완료 0개`를 표시합니다.
- 결과 화면은 `복원 완료 · 사건 5개`로 표시합니다.
- 데스크톱은 도움말·교사용 안내·업데이트 내역 세 버튼을 유지합니다.
- 640px 이하에서는 `도움말`과 `더보기` 두 버튼만 보이고, 더보기 안에 교사용 안내와 업데이트 내역을 둡니다.
- `업데이트 내역`에는 `2026-07-18 · v1.1.0`과 학생 언어, 단계 집중, 모바일 개선 내용을 최신 항목으로 추가합니다.

### 5.2 첫 안내

- 제목 아래에 8개 달 모양을 순서대로 보여 줍니다.
- `밝은 부분이 커져요`와 `밝은 부분이 작아져요` 구간을 색이 아니라 텍스트와 화살표로 표시합니다.
- 마지막 달에서 첫 달로 이어지는 `다시 반복` 표시를 둡니다.
- 필수 체크박스 5개를 제거하고 다음 세 개의 짧은 `기억할 점` 카드로 바꿉니다.
  1. 달이 잘린 게 아니에요. 우리가 보는 밝은 부분의 모양이 달라져요.
  2. 달은 햇빛을 반사해서 밝게 보여요.
  3. 이 그림은 연습용이에요. 오늘의 달을 알려 주는 달력은 아니에요.
- 카드는 읽기 정보이며 누르지 않아도 됩니다. 하나의 `준비됐어요, 사건 시작!` 버튼으로 시작합니다.
- 모바일에서 8개 모양은 두 구간으로 나누되, 현재보다 카드 높이와 문장 길이를 줄여 시작 버튼까지의 거리를 줄입니다.

### 5.3 사건 단계

사건 상단의 관측 기록판은 모든 단계에서 유지하여 학생이 앞뒤 달을 다시 볼 수 있게 합니다.

기록판 아래에 5단계 진행표를 둡니다.

1. 날짜 순서 보기
2. 달 모양 고르기
3. 앞뒤 까닭 고르기
4. 밝은 부분 변화 고르기
5. 답을 하나로 정할지 고르기

각 단계 상태는 `지금`, `완료`, `다음` 텍스트와 아이콘으로 함께 표시합니다. 색만으로 상태를 전달하지 않습니다.

#### 현재 단계

- 현재 단계의 질문과 선택지만 펼칩니다.
- 선택 후 `다음: …` 버튼을 눌러 단계가 넘어갑니다.
- 단계 이동 뒤 새 질문 제목으로 키보드 초점을 옮기고, 모바일에서는 `scrollIntoView({ block: "start" })`로 질문을 화면 위쪽에 맞춥니다.
- 앞뒤 까닭 단계는 각 기록마다 두세 개 문장을 제시하고 하나씩 고르게 합니다. 정답 문장만 체크하도록 요구하지 않습니다.
- 예를 들어 첫 사건의 앞 기록 질문은 `앞 달보다 밝은 부분이 커요`, `앞 달보다 밝은 부분이 작아요`, `앞 달과 밝은 부분이 비슷해요` 중 하나를 고릅니다.
- 앞 기록과 뒤 기록은 서로 다른 `fieldset`과 라디오 그룹으로 구분합니다.

#### 완료 단계

- 선택 결과를 한 줄로 요약합니다. 예: `달 모양: 상현 무렵`.
- `고치기` 버튼을 제공하며, 이전 단계를 고치면 그 선택에 의존하는 뒤 단계 답을 초기화합니다.
- 날짜 순서 단계는 다시 풀 입력이 없으므로 `날짜 순서를 확인했어요`로만 요약합니다.

#### 다음 단계

- 제목과 `앞 단계를 끝내면 열려요`만 짧게 표시합니다.
- 비활성 라디오·체크박스 전체는 렌더링하지 않습니다.

### 5.4 최종 확인과 오류 복구

- 모든 단계에 답하기 전에는 최종 버튼을 보여 주지 않습니다.
- 5단계를 마치면 답 요약과 `내 생각 확인하기` 버튼을 보여 줍니다.
- 판정이 맞으면 기존 성공 설명과 다음 사건 버튼을 표시합니다.
- 판정이 맞지 않으면 첫 번째로 다시 볼 단계만 펼칩니다.
- 열린 단계 바로 위에 `이 단계를 다시 살펴봐요`와 사건별 도움 문장을 표시합니다.
- 판정 결과의 다른 미통과 단계는 한꺼번에 나열하지 않습니다. 한 단계씩 고친 뒤 다시 확인합니다.
- 오류 안내는 `aria-live="polite"`로 읽히고, 열린 단계 제목으로 초점이 이동합니다.

## 6. 구성 요소와 책임

### 기존 구성 요소 변경

- `AppHeader`: `stage`를 받아 준비·사건·완료 문구를 구분하고 모바일 안내 메뉴를 제어합니다.
- `GuidePanel`: 달 순환 구간과 세 개의 기억할 점을 보여 주며 강제 체크 상태를 제거합니다.
- `CaseWorkspace`: 답 초안과 판정은 유지하되 현재 단계, 완료 요약, 수정·다음 행동을 관리합니다.
- `MoonPhase`: 그림 책임만 유지합니다.
- `ObservationBoard`: 사건 전체에서 계속 보이는 관측 기록판 역할을 유지합니다.
- `cases.ts`, `phases.ts`: 학생 문구와 근거 선택지를 쉬운 표현으로 조정합니다. 후보·변화 방향·확신도의 기존 정답 집합은 변경하지 않습니다.
- `types.ts`, `judge.ts`: 근거 선택지마다 정답 여부를 구분하고, 앞·뒤에서 각각 맞는 근거를 골랐는지 판정합니다.

### 새 구성 요소

- `PhaseCycleGuide`: 8개 달 모양, 커지는 구간, 보름 전환, 작아지는 구간, 반복 표시를 담당합니다.
- `CaseStepProgress`: 5개 단계의 지금·완료·다음 상태만 표시합니다.
- `CompletedStepSummary`: 완료 답 요약과 고치기 버튼을 표시합니다.
- `MobileInfoMenu`: 모바일에서 교사용 안내와 업데이트 내역 진입을 제공합니다.

모든 코드 파일은 500줄 미만을 유지합니다. `CaseWorkspace.tsx`는 현재 253줄이므로 단계별 표시 로직을 별도 구성 요소와 순수 도우미로 분리하여 350줄 아래를 목표로 합니다.

## 7. 상태와 데이터 흐름

`CaseWorkspace`의 답 초안 필드는 기존과 같습니다.

```ts
type Draft = {
  orderConfirmed: boolean;
  candidateIds: PhaseId[];
  evidenceIds: string[];
  trendId: TrendChoiceId | null;
  certainty: Certainty | null;
};
```

화면 상태를 다음처럼 추가합니다.

```ts
type CaseStep = "order" | "candidate" | "evidence" | "trend" | "certainty" | "review";

type StepFeedback = {
  step: Exclude<CaseStep, "order" | "review">;
  message: string;
} | null;
```

근거는 정답 문장만 저장하던 구조에서 선택지 구조로 바꿉니다.

```ts
type Evidence = {
  id: string;
  side: "before" | "after";
  label: string;
  accepted: boolean;
};
```

- `getNextStep(draft, caseData)`는 답의 완성도만 보고 열 단계 또는 `review`를 반환합니다.
- `getFirstRetryStep(judgeResult)`는 판정 실패 중 가장 먼저 고칠 단계를 반환합니다.
- `editStep(step)`은 해당 단계와 그 뒤의 의존 답을 초기화합니다.
- `CaseAnswer.evidenceIds`는 앞·뒤에서 고른 두 근거 ID를 계속 저장합니다.
- `judgeAnswer`는 앞·뒤 각각 `accepted: true`인 근거 하나를 골랐는지 확인합니다. 같은 쪽의 오답 근거는 통과로 인정하지 않습니다.
- 후보·변화 방향·확신도에 관한 기존 판정 규칙과 `CaseAnswer`의 외부 구조는 변경하지 않습니다.
- 페이지 새로고침 시 초기화되는 기존 메모리 상태 정책을 유지합니다.

## 8. 접근성과 반응형 기준

- 모든 버튼과 선택 행의 터치 영역은 최소 44×44px입니다.
- 폼 그룹은 `fieldset`과 `legend`를 유지합니다.
- 진행표의 현재 상태에는 `aria-current="step"`을 사용합니다.
- 단계가 바뀌면 제목에 프로그래밍 방식으로 초점을 옮깁니다.
- 포커스 윤곽선은 기존 금색 4px 스타일을 유지합니다.
- 애니메이션은 짧은 펼침과 위치 이동에만 사용하며 `prefers-reduced-motion: reduce`에서는 제거합니다.
- 320px부터 가로 스크롤이 없어야 합니다.
- 모바일에서 관측 기록 세 장은 세로 타임라인을 유지하고, 단계 패널은 화면 폭을 모두 사용합니다.
- 교사용 안내와 업데이트 내역은 학생의 주 행동보다 시각적으로 앞서지 않습니다.

## 9. 테스트 설계

모든 행동 변경은 테스트를 먼저 작성하고 실패를 확인한 뒤 구현합니다.

### 단위·컴포넌트 테스트

- 안내 화면에 필수 체크박스가 없고 세 개의 기억할 점과 시작 버튼이 나타납니다.
- 안내 중 헤더가 `준비 단계`를 표시하고, 사건 시작 뒤 `사건 1 / 5`를 표시합니다.
- 처음에는 날짜 단계만 펼쳐지고 다음 단계 입력은 DOM에 나타나지 않습니다.
- 날짜 단계 완료 후 후보 단계와 `다음` 버튼이 나타납니다.
- 후보를 고친 뒤 근거·변화·확신 답이 초기화됩니다.
- 앞·뒤 근거를 각각 고르기 전에는 변화 단계로 넘어갈 수 없습니다.
- 앞·뒤 근거에서 오답 문장을 고르면 해당 근거 단계가 다시 열립니다.
- 모든 답이 채워지기 전에는 최종 확인 버튼이 나타나지 않습니다.
- 오답 제출 시 첫 재검토 단계만 열리고 해당 도움 문장이 표시됩니다.
- 단일 답 사건과 복수 가능 답 사건 모두 마지막까지 진행됩니다.
- 모바일 안내 메뉴는 키보드와 Escape로 열고 닫을 수 있으며 원래 버튼으로 초점이 돌아갑니다.
- 업데이트 내역 최상단에 `2026-07-18 · v1.1.0`이 나타납니다.

### 렌더링·브라우저 검증

- 기존 Vitest·Testing Library 전체 테스트를 통과합니다.
- 정적 렌더 HTML 테스트에서 핵심 제목과 과학 안전 문구가 남아 있는지 확인합니다.
- 375×812, 768×1024, 1280×720에서 안내와 첫 사건을 캡처합니다.
- 학생 흐름으로 사건 1개를 끝까지 수행하고, 오답 수정과 다음 사건 이동을 확인합니다.
- 키보드만으로 안내 시작, 단계 이동, 수정, 최종 확인, 대화상자 닫기를 수행합니다.
- 콘솔 오류와 hydration 경고가 없어야 합니다.

## 10. 제외 범위

- 사건 수, 정답 집합, 점수·배지·시간 제한을 추가하지 않습니다.
- 실제 날짜 달 계산, 위치·사진·계정·저장 기능을 추가하지 않습니다.
- 달 위상 원인의 3D 시뮬레이션을 추가하지 않습니다.
- 전체 시각 콘셉트나 색상 체계를 새로 만들지 않습니다.
- 교사용 대시보드나 학생별 기록 기능을 추가하지 않습니다.
